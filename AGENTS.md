# FloatPlayer

## Работа с проектом

- Отвечай по-русски, кратко. Сначала прочитай `openspec/config.yaml` и актуальный
  `STATUS.md`, затем сверь затронутые участки кода. Сохраняй чужие изменения.
- Будущие функциональные доработки веди через **OpenSpec**: proposal → specs →
  design → tasks → реализация → проверки → archive. Это выбранный пользователем
  процесс проекта; параллельный Spec Kit не требуется.
- Инструкция: `docs/openspec.md`. Навыки Codex: `.agents/skills/openspec-*`.
  Если навыки ещё не обнаружены, следуй их SKILL.md или используй локальный CLI
  `npm run openspec -- <command>`; не подменяй спецификации одним STATUS.md.
- До изменения кода сформулируй ожидаемое поведение и критерии готовности.
  Разрешённую реализацию продолжай без повторного согласования обычных решений.
- Используй vanilla JS/CSS, Manifest V3 и существующие команды проекта.
  Учитывай порядок загрузки content scripts и ресурсы в manifest.json.
- Проверки: `npm run spec:check`, `npm run check`, `npm test`; при изменениях
  расширения — `npm run build`. Для UI запусти `npm run preview` и проверь
  сценарий и внешний вид через доступный CUA. Стенд не заменяет живой YouTube.
- В конце обнови STATUS.md, просмотри diff и укажи фактически выполненные
  проверки и ограничения. Commit/push/deploy требуют разрешения пользователя.
- Каталоги `!notes` — личные заметки: не читай, не изменяй и не публикуй их.
  Сохраняй экранированный паттерн `\!notes/` в .gitignore; не снимай уже
  отслеживаемые заметки с отслеживания без отдельного разрешения.
