# План: ночной режим по клику на Луну (вариант B — SVG feColorMatrix)

Прежний план (фикс next/prev) выполнен, лежит в git-истории.

## Цель

Луна на панели PiP-окна становится кнопкой. Клик циклом переключает
подавление синего света в видео: `off → warm → deep → off`.
Выбор запоминается между сессиями.

## Ключевые решения

1. **Луна уезжает из `<label class="ytfp-sleep">`.**
   Сейчас иконка внутри label, который принадлежит `<select>` таймера сна
   (pip-controls.js:425) — клик по иконке открывал бы список минут. Делаем
   отдельную `<button class="ytfp-btn">` через существующий `createButton()`
   и ставим её перед `sleepWrap`. Таймер сна остаётся с тем же select,
   но уже без иконки.

2. **Фильтр — через класс на `<body>` PiP-окна, а не inline-стиль.**
   ```
   body.ytfp-night--warm video.html5-main-video { filter: url(#ytfp-night-warm); }
   body.ytfp-night--deep video.html5-main-video { filter: url(#ytfp-night-deep); }
   ```
   Почему так: `<body>` живёт только внутри PiP-окна и умирает вместе с ним.
   Значит **уборка не нужна вообще** — видео возвращается на страницу чистым.
   Inline-стиль пришлось бы снимать вручную, и он бы протёк на страницу,
   если бы `<video>` подменился при переходе к следующему ролику.

3. **Матрицы (feColorMatrix, диагональ R/G/B):**

   | Уровень | R | G | B |
   |---------|---|---|---|
   | warm    | 1.00 | 0.93 | 0.72 |
   | deep    | 1.00 | 0.82 | 0.50 |

   Честное масштабирование каналов — то же, что делает f.lux. В отличие от
   `sepia()` не мутит картинку и не съедает насыщенность.

4. **Нативный режим (`windowMode: "native"`) трогать не надо.**
   Там `buildBar()` вообще не вызывается — кнопки не будет автоматически.
   CSS-фильтры в окно ОС всё равно не доходят.

5. **Хранение:** новый ключ `nightMode: "off"` в `YTFP.DEFAULT_SETTINGS`.
   Читаем `YTFP.settings.get().nightMode`, пишем `chrome.storage.sync.set` —
   тот же приём, что уже используется для `audioPreset` (pip-controls.js:283).

6. **Индикация:** класс `.ytfp-btn--active` (уже есть в CSS) на кнопке при
   warm/deep, плюс тёплый цвет иконки — амбер на warm, оранжевый на deep.
   Отдельных строк локализации на каждый уровень не заводим: одна строка
   `nightTooltip`, состояние видно глазами. Меньше правок в 14 языках.

## Шаги

1. **`constants.js`** — добавить `nightMode: "off"` в `DEFAULT_SETTINGS`.
   → verify: `YTFP.settings.get().nightMode === "off"` на свежем профиле.

2. **`pip-controls.js`** — вставить `<svg>` с двумя `<filter>` в `pipDocument.body`
   при сборке панели.
   → verify: `pipDocument.querySelector("#ytfp-night-warm")` находится.

3. **`pip-controls.js`** — убрать `createIcon(..., "sleep")` из `sleepWrap.append(...)`,
   создать `nightButton` через `createButton`, вставить в `bar.append(...)`
   перед `sleepWrap` (обе ветки: shorts и обычная).
   → verify: клик по Луне НЕ открывает выпадашку таймера сна.

4. **`pip-controls.js`** — цикл состояний + запись в storage + класс на `body`
   и на кнопке. Стартовое состояние читаем из настроек при сборке панели.
   → verify: три клика возвращают в исходное; после закрытия и повторного
   открытия окна уровень тот же.

5. **`pip.css`** — правила `body.ytfp-night--warm/deep` и цвета иконки.
   → verify: картинка теплеет, панель и текст на ней НЕ красятся
   (фильтр висит только на `video`).

6. **`_locales/*/messages.json`** — ключ `nightTooltip` в 14 языках.
   → verify: одинаковое число ключей во всех файлах.

7. **Проверка возврата** — вернуть видео на страницу при активном ночном режиме.
   → verify: плеер на youtube.com обычного цвета, без остаточного фильтра.

## Риски

- **Производительность.** `filter: url(#svg)` Chrome обычно превращает в
  GPU-фильтр Skia, но на 4K возможен провал в софтверный рендер. Если
  заметим просадку — откатываемся на шорткат `sepia()+hue-rotate()`
  (вариант A), правка на 3 строки CSS.
- **DRM-контент** (арендованные фильмы) под фильтром может дать чёрный кадр.
  Обычных роликов не касается.

## Не делаем

- Страницу options не трогаем: режим переключается прямо в окне, отдельная
  галочка не нужна.
- Юнит-тестов не добавляем: код целиком завязан на DOM PiP-окна,
  в `tests/utils.test.js` тестируются только чистые функции.

## Объём

~70 строк JS + ~20 строк CSS + 14 строк локализаций. Существующий код не
рефакторим, трогаем только то, что нужно для фичи.
