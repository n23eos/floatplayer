# План: шортсы по ключевому слову

Одобрено. Разведка (реальный YouTube, вкладка Chrome) показала:

- id шортсов по слову достаются fetch-ем `/results?search_query=…&sp=…`
  с той же вкладки, парсинг `ytInitialData` + запасной regex по `/shorts/<id>`;
- переход на произвольный шортс без перезагрузки страницы возможен только
  через `ytd-app.fire("yt-navigate", {endpoint})` — синтетический клик по
  `<a>` даёт полную перезагрузку и убил бы PiP-окно;
- `#shorts-player` и `<video>` при `yt-navigate` не пересоздаются — плеер,
  вынесенный в PiP-окно, переживает переход (проверено метками на узлах).

## Архитектура

1. `content/yt-navigate-bridge.js` — новый, world: "MAIN" (отдельный блок в
   manifest.json). Контент-скрипты живут в изолированном мире и `app.fire`
   не видят. Мостик слушает `window.postMessage`, принимает только
   `{type: "ytfp-shorts-navigate", videoId}` от самого окна, валидирует id
   по `/^[A-Za-z0-9_-]{11}$/` и сам собирает endpoint. Никаких данных
   насквозь: наружу уходит только проверенный id.

2. `content/shorts-search.js` — новый, изолированный мир:
   - `extractShortsIds(html)` — чистая функция, два пути разбора
     (ytInitialData + regex по ссылкам), объединение без дублей. CJS-экспорт
     для vitest, как в utils.js.
   - `search(query)` — fetch выдачи, кэш списка id, индекс.
   - `next()/prev()` — шаг по списку (по краям — стоим, не заворачиваем),
     навигация через postMessage мостику.
   - `isActive()` — режим поиска включён.

3. `pip-controller.js` — goNext/goPrev и автопереход: если режим поиска
   активен, шаг по списку; иначе прежние кнопки ленты.

4. `pip-controls.js` — в капсуле шортсов кнопка-лупа. Клик — поле ввода
   (капсула-строка над основной капсулой). Enter — поиск и переход к
   первому найденному; пустой результат — красная рамка. Esc/повторный
   клик — выход из режима, дальше обычная лента.

5. `pip.css` — стили поля.

6. Локали ×14: подсказка лупы, placeholder.

7. Тесты: `extractShortsIds` (фикстуры-строки), шаги списка.

## Ограничения v1

- Пачка 32 id без continuation: дошли до конца — стоим на последнем
  (автопереход выключается сам собой, некуда идти).
- Выход из режима не возвращает старую ленту — YouTube уже ушёл с неё;
  дальше работает обычная навигация по текущей ленте.
