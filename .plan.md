# План: Chrome-расширение «YouTube FloatPlayer» (рабочее название)

## 1. Концепция

Кнопка в нижней панели плеера YouTube (рядом с настройками/PiP). Клик — видео
выносится в отдельное окно **поверх всех окон** со своим полноценным набором
элементов управления. Пользователь продолжает работать в других приложениях,
видео всегда видно.

### Ключевое техническое решение (наше преимущество)

Используем **Document Picture-in-Picture API** (Chrome 116+):

- Это единственный способ в Chrome получить настоящее окно «поверх всех окон»
  (always-on-top на уровне ОС) **с произвольным HTML внутри**.
- Старые расширения-конкуренты либо используют обычный video-PiP (только
  play/pause, никаких настроек), либо открывают обычное popup-окно, которое
  **не** держится поверх других окон.
- Мы переносим сам `<video>`-элемент со страницы в PiP-окно (без пересоздания
  потока), поэтому: нет двойного воспроизведения, работает залогиненный аккаунт,
  качество/история просмотра сохраняются, реклама и Premium работают как обычно.

### Честные ограничения (заявляем сразу, не обещаем невозможное)

- Требуется Chrome 116+ (2023 г.) — сегодня это >95% пользователей Chrome.
- Прозрачность окна и «клик сквозь окно» невозможны в Chrome API — это могут
  только нативные приложения. Не делаем, не обещаем.
- Одно PiP-окно на браузер (ограничение API).

## 2. Анализ конкурентов и наши отличия

| Конкурент | Слабость | Наш ответ |
|---|---|---|
| Нативный PiP Chrome | Только play/pause/next, нет перемотки по таймлайну, скорости, громкости | Полный плеер: таймлайн, скорость, громкость, субтитры |
| «Floating for YouTube» | Открывает iframe в popup — окно НЕ поверх всех окон, отдельная сессия плеера | Document PiP = настоящий always-on-top + тот же видеопоток |
| «Enhancer for YouTube» | Комбайн из 50 функций, PiP — побочная фича, тяжёлый | Один юзкейс, лёгкое, быстрое, ноль лишних разрешений |
| «Separate Window» | Обычное окно, теряет фокус | Always-on-top через Document PiP |

## 3. Функции

### MVP (фаза 1–3)

1. **Кнопка в панели плеера YouTube** — нативно выглядящая, с tooltip, тёмная/светлая тема.
2. **Вынос видео в always-on-top окно** (Document PiP, перенос `<video>`).
3. **Свои контролы в PiP-окне**: play/pause, таймлайн с превью-временем,
   громкость, скорость (0.25x–3x c шагом 0.25), субтитры вкл/выкл,
   кнопка «вернуть на страницу».
4. **Запоминание размера окна** между сессиями.
5. **Автовозврат** видео на страницу при закрытии PiP-окна.

### Дополнительные функции (фаза 4) — то, что делает нас лучшими

6. **A-B повтор** — зациклить фрагмент (для обучающих видео, музыки, разбора движений).
7. **Плейлист-навигация** — след./пред. видео плейлиста прямо из PiP-окна.
8. **Главы (chapters)** — маркеры глав на таймлайне PiP-плеера.
9. **Усиление громкости до 300%** (Web Audio API gain) — частый запрос для тихих видео.
10. **Горячие клавиши** (chrome.commands, работают когда фокус в Chrome):
    открыть/закрыть PiP, пауза, ±5 сек, скорость.
11. **Авто-PiP** (опция, выкл. по умолчанию): при уходе с вкладки YouTube видео
    само выносится в окно (через Media Session `enterpictureinpicture`).
12. **Компактный режим**: при наведении — контролы, без наведения — чистое видео.
13. **Настройки** (страница options): поведение по умолчанию, шаг скорости,
    авто-PiP, положение кнопки.

### Осознанно НЕ делаем (YAGNI)

- Скачивание видео (нарушение ToS, бан в Web Store).
- Блокировка рекламы (отдельный юзкейс, риск бана).
- Поддержка других сайтов в v1 (Twitch/Vimeo — возможное v2).
- Прозрачность/click-through (невозможно в Chrome).

## 4. Архитектура

Manifest V3. Без сборщика в MVP (ванильный JS/ES-модули) — минимум сложности.

```
extension/
├── manifest.json          # MV3, permissions: storage; host: youtube.com
├── content/
│   ├── inject-button.js   # находит панель плеера, вставляет кнопку (MutationObserver — SPA-навигация YouTube)
│   ├── pip-controller.js  # открытие Document PiP, перенос <video>, возврат
│   └── player-api.js      # обёртка над ytplayer: скорость, главы, плейлист, субтитры
├── pip/
│   ├── pip.css            # стили окна PiP
│   └── controls.js        # UI контролов внутри PiP-окна
├── background/
│   └── service-worker.js  # горячие клавиши (chrome.commands) → сообщения в content script
├── options/
│   ├── options.html/js    # страница настроек (chrome.storage.sync)
└── icons/
```

Потоки данных:

- Кнопка/хоткей → `pip-controller` → `documentPictureInPicture.requestWindow()`
  → перенос `<video>` в PiP-окно → `controls.js` управляет им напрямую.
- Закрытие окна (`pagehide`) → видео возвращается в исходный контейнер на странице.
- Настройки: `chrome.storage.sync`, читаются content-скриптом при старте.

Обработка ошибок:

- Chrome < 116 / API недоступен → фолбэк на нативный `video.requestPictureInPicture()` + уведомление.
- YouTube поменял DOM (кнопка не встала) → лог + фолбэк-кнопка поверх плеера.
- Видео в рекламе → кнопка неактивна до конца рекламы.

## 5. Фазы разработки

Каждый шаг → verify-критерий.

### Фаза 1. Каркас (0.5 дня)
1. manifest.json MV3 + пустой content script → verify: расширение грузится, console.log на youtube.com.
2. Вставка кнопки в панель плеера + выживание при SPA-навигации → verify: кнопка есть на /watch, остаётся после перехода между видео.

### Фаза 2. Ядро PiP (1 день)
3. Document PiP: перенос видео, возврат при закрытии → verify: окно поверх всех окон, видео играет без прерывания, после закрытия видео снова на странице.
4. Фолбэк для старых Chrome → verify: при отключённом API открывается нативный PiP.

### Фаза 3. Контролы (1–2 дня)
5. Play/pause, таймлайн, громкость → verify: перемотка синхронна с основной страницей.
6. Скорость, субтитры, «вернуть» → verify: скорость меняется, сохраняется при возврате.
7. Запоминание размера окна → verify: переоткрытие с прежним размером.

### Фаза 4. Дифференциаторы (2–3 дня)
8. A-B повтор → verify: фрагмент зацикливается, сброс работает.
9. Плейлист next/prev + главы на таймлайне → verify: переключение видео не закрывает PiP-окно.
10. Усиление громкости (Web Audio) → verify: 300% слышимо громче, без искажений на 100%.
11. Горячие клавиши → verify: работают при фокусе на любой вкладке Chrome.
12. Авто-PiP (опция) → verify: уход со вкладки выносит видео, возврат — возвращает.

### Фаза 5. Настройки и полировка (1 день)
13. Options-страница + storage.sync → verify: настройки применяются без перезагрузки.
14. Темы (тёмная/светлая по prefers-color-scheme), иконки, локализация ru/en → verify: визуальная проверка.

### Фаза 6. Тесты и публикация (1 день)
15. Юнит-тесты утилит (парсинг глав, форматирование времени, A-B логика) — vitest → verify: coverage ключевой логики.
16. Ручной E2E-чеклист: обычное видео, плейлист, Shorts (кнопку не показываем), live-стрим, реклама, смена видео в PiP.
17. Упаковка, скриншоты, текст для Chrome Web Store.

Итого: ~6–8 дней работы.

## 6. Риски

- **YouTube меняет DOM** — главный риск. Митигация: селекторы в одном конфиге,
  фолбэк-кнопка, быстрые патч-релизы.
- **Ad-плеер перехватывает video-элемент** — во время рекламы блокируем вынос.
- **Ревью Web Store** — минимальные permissions (`storage` + host youtube.com),
  без remote code → быстрый апрув.
